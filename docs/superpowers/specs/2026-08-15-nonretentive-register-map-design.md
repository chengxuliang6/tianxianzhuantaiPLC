# Easy521 非保持寄存器迁移设计

## 背景与目标

AutoShop V4.12.0.2 与 Easy521 固件 V6.11.0.2 的现场验证表明：自定义变量绑定软元件后，掉电保持属性由软元件地址决定；`D0～D999` 掉电不保持，`D1000` 及以后掉电保持，而且该范围不能修改。原协议把命令、状态和对时区放在 `D1000～D1206`，与“上电后不得重放旧命令”的安全要求冲突。

本次迁移把控制协议中需要安全复位的字段移到非保持区，同时保留大容量逐度事件缓冲区。迁移完成前，现有硬件版电脑程序不得连接或写入 PLC，PLC 工程不得下载。

## 地址设计

### 命令与参数：D0～D19

| 新地址 | 原地址 | 字段 |
|---:|---:|---|
| D0 | D1000 | MODE |
| D1 | D1001 | DIRECTION，`1=正转`、`-1=反转` |
| D2 | D1002 | SPEED_INDEX，`1/2/3/4/5` 对应 `1/2/4/5/10°/s` |
| D3 | D1003 | START_SEQ |
| D4 | D1004 | STOP_SEQ |
| D5 | D1005 | SET_ZERO_SEQ |
| D6 | D1006 | RESET_FAULT_SEQ |
| D7 | D1007 | POWER_SEQ |
| D8 | D1008 | HEARTBEAT |
| D9 | D1009 | BUFFER_ACK_SEQ |
| D10:D11 | D1010:D1011 | TOTAL_RATIO，i32×1000 |
| D12:D13 | D1012:D1013 | ACCELERATION，i32×1000 |
| D14:D15 | D1014:D1015 | DECELERATION，i32×1000 |
| D16:D17 | D1016:D1017 | SOFTWARE_STOP_DECELERATION，i32×1000 |
| D18:D19 | D1018:D1019 | BACKLASH_COMPENSATION，i32×1000 |

### 状态与运行元数据：D100～D120

`D1100～D1120` 按字段顺序一一迁移为 `D100～D120`。包括运行状态、状态标志、故障码、位置、目标、速度、心跳回显、各命令确认序号、事件数量、事件代数、运行结果和运行开始毫秒计数。

### 协议与对时：D200～D206

`D1200～D1206` 按字段顺序一一迁移为 `D200～D206`：

- `D200`：PROTOCOL_VERSION，固定为 `2`；
- `D201:D202`：WORD_ORDER_PROBE，固定为 `0x12345678`，高字在前；
- `D203`：TIME_SYNC_REQUEST_SEQ；
- `D204:D205`：PLC_TICK_MS；
- `D206`：TIME_SYNC_RESPONSE_SEQ。

协议版本升级为 2 是破坏性地址迁移的连接门禁。电脑程序只有在新地址同时读到版本 `2` 和字序魔数后，才允许任何写操作。

### 逐度事件缓冲：D2000～D4159

事件缓冲仍为 360 条记录，每条 6 个 16 位字，总计 2160 字。Easy521 会使该范围掉电保持，但重启后的旧内容不能自动恢复为有效运行证据：

- 事件有效性只由非保持区 `D116` 的 EVENT_COUNT、`D117` 的 EVENT_GENERATION、`D118` 的 RUN_STATUS 与状态标志共同证明；
- PLC 重启后这些元数据恢复为安全初值，旧事件字即使仍在 `D2000～D4159`，也视为无效且不得下载或 ACK；
- 电脑端若在保持连接期间观察到 PLC 毫秒计数回退且不能由 32 位自然回绕解释，必须判定 PLC 已重启，丢弃旧运行会话、对时模型和已发布缓冲缓存，并要求重新完成协议探针；
- 下一次被正式接受的运行可以覆盖无效的旧事件字；
- 运行中断电产生的不完整事件不承诺恢复，现场记录应标记为断电作废。

## AutoShop 变量命名

变量名反映新地址，避免名称和软元件地址不一致：

- `iD0000Mode` 至 `iD0019BacklashLo`；
- `iD0100RunState` 至 `iD0120RunStartTickLo`；
- `iD0200ProtocolVersion` 至 `iD0206TimeSyncResponse`；
- `aD2000Events` 保持不变。

所有 `D0～D206` 变量均应由 AutoShop 自动显示为“不保持”和“私有”。`aD2000Events` 会自动显示为“保持”和“私有”，这是硬件固定属性，不手工覆盖。

## 软件与PLC行为

PLC 参考程序只使用新变量名和新地址。电脑端寄存器常量、连接探针、读写分组、模拟器、CSV会话协调和UI不得保留旧地址依赖。电脑端在协议探针失败、版本不为 2、字序不匹配、检测到未经重新探针的PLC重启或状态快照不完整时保持只读失败状态，不发送 START、POWER、SET_ZERO、RESET 或参数写入。

已有模拟器继续表现为无PLC模式，但必须发布协议版本 2 和新地址布局。Windows EXE 必须在全部自动化测试通过后重新构建，并更新交付清单中的大小、时间和 SHA-256。

## 迁移与验证顺序

1. 先修改测试，使旧地址布局产生预期失败。
2. 修改电脑端寄存器常量、客户端、模拟器和控制器适配。
3. 修改PLC参考源、变量表说明和寄存器合同。
4. 运行PC完整测试、PLC静态合同测试、模拟端到端测试和打包烟雾测试。
5. 重新生成Windows EXE并记录SHA-256。
6. AutoShop 中先只录入新变量表，离线编译达到0错误、0警告。
7. 在下载前再次核对伺服未使能、电机静止、机械区域清空；获得用户明确确认后才允许通过USB下载。
8. 下载后的首次验证只读 `D200:D202`，必须得到版本2和 `0x12345678`；未通过时禁止任何硬件写入。

## 验收标准

- 仓库中不存在把命令、状态或对时字段映射到 `D1000～D1206` 的有效代码或操作说明；历史迁移说明可以保留原地址作为背景。
- 自动化测试证明新地址、协议版本2、字序门禁、PLC重启检测和不确定连接状态下禁止写入。
- AutoShop 新变量表显示 `D0～D206` 为不保持，离线编译0错误、0警告。
- 新EXE通过无PLC模拟器烟雾测试；真实PLC运动仍须按现场调试清单从空载、1°/s、小位移开始，不批准直接整圈或高速测试。
